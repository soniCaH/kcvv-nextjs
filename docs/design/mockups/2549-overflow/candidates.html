What happens to a name that does not fit its slot?

The site has four idioms for a string longer than its slot — cut to one line (truncate, 16 sites), cut to N lines (line-clamp-N, 16 sites, N ∈ {1,2,3}), wrap-and-hyphenate (hyphens-auto, 9 sites), and do nothing at all. Nothing chooses between them. This round asks only the governing question: what decides which idiom a slot gets?

  • Every string below is real production data, read today. K Hoger Op Wolvertem Merchtem (29 chars) is this season's longest opponent on /ploegen/eerste-elftallen-a/wedstrijden.
  • Every panel is the 343px phone track — a 375px viewport minus its gutters. This is where the cut bites.
  • PRODUCT.md:103 rules out "hover-only affordances" for this audience, which kills the title-attribute recovery that 4 of the 10 truncating files use today.
  • A cut is sighted-only: CSS truncation leaves the whole string in the DOM, so a screen reader always gets the full name.

Round 2 — so what is a row, and what is a card?

★ Locked — 2026-08-12 — Reading 3, the label register picks the bucket

A row stays a row (round 1) and cuts. For every slot that is not already a row, the type register names the bucket: mono / label type cuts to one line, display and body type clamps to N lines. So the match hero's two clubs render whole, a role inside a person card cuts, a squad-grid name clamps, and a download control's label clamps — and its height stops being fixed, which is the accepted cost.

Why this reading: it reuses a split the site already made — #2516's display face when the number is the subject, mono when it is a tag — so a mono label is already the site's way of saying "this is a tag, not a sentence", and a tag is the thing that survives being cut. It also needs no per-surface judgement, which is what rule A was chosen for. Rejected: reading 1 (the box decides) because it half-shows the match page's own subject in its largest type; reading 2 (the subject is exempt) because "subject" is a judgement call written down per surface.

Rule A keys on the slot, which means the slot has to be nameable. Most surfaces are obvious: an agenda row is a row, a news card is a card. Four are not, and they are exactly the four where today's idioms disagree with each other. Same four surfaces in every panel, same real data, only the reading of rule A changes.

Round 4 — how many lines does a clamped card get?

★ Locked — 2026-08-12 — 3/2, headline three lines, lead two

A clamped headline gets 3 lines, a clamped lead gets 2. The headline is the card's identity and the only thing that names the article, so it renders whole — measured on production, /nieuws headlines run 76 / 65 / 56 / 56 / 55 characters, which is three lines of 18px display italic on a 319px card. Any two-line rule would cut most of the site's real headlines, which is what ruled out 2/2 and 2/3 on evidence. The lead gets 2 because it is a sample, not a summary — the same reasoning round 1 used to let prose be cut at all.

Rejected: 3/3 because a 177-character lead then renders almost complete and the card competes with the article instead of pointing at it. Accepted cost: three lines of display italic over two of body is headline-heavy on a small card.

The site ships three answers: 11× line-clamp-2, 3× -3, 2× -1. The clearest contradiction is the same pair of fields on two routes — NewsCard gives a headline 3 lines and its lead 3; SearchResult gives the identical headline 2 and its lead 2; MatchArticleLinkCard gives the headline no cap at all and its lead 2. Round 5 — where does hyphenation belong?

★ Locked — 2026-08-12 — Option a, delete all eight and write the rule

No slot carries a hyphenation declaration. The six hyphens-auto declarations and the two break-words declarations are removed — all eight are provably inert on the site's real content, so this is a deletion of dead declarations, and it leaves the site uniform by construction rather than with an arbitrary six. Count corrected during resolution: the drill said nine + two, which counted docblock lines as sites; the real figure is six + two across eight files.

The rule moves to DESIGN.md, where it outlives the two components currently carrying it as comments: if a slot ever needs hyphenation, hyphens-auto goes in alone, never paired with break-words (#2269 — the emergency per-character breaks out-compete the hyphenator and produce hyphen-less mid-word clips). Accepted risk, on the record: if content or a breakpoint ever produces a word wider than its slot, it clips rather than hyphenates, guarded only by that written rule.

There is no visual comparison to make here, and that is the finding. Four panels were built and rendered identically — not a mockup bug, a measurement. Every real string on this site, at every real slot width, breaks in exactly the same place with hyphens: auto on, off, or replaced by break-words. Measured in Chrome against the loaded Typekit faces, reconstructing the rendered line boxes character by character.

So the decision is not aesthetic

a — Delete them all, write the rule instead. Six hyphens-auto plus two break-words, all provably inert. The #2269 knowledge moves from a code comment into DESIGN.md, where it survives the components. Uniform by construction: zero sites carry it. Risk: a future longer word clips instead of hyphenating, unguarded.

b — One rule, applied to every clamped slot. hyphens-auto, alone, never with break-words. Costs nothing at runtime and is correct the day content outgrows a slot. Risk: adds a class to ~10 more sites for zero present effect.

c — Keep the nine, delete only the two break-words. Ratifies what ships and removes the one declaration #2269 identifies as harmful. Risk: nine arbitrary sites carry it and the rest do not — which is not a decision.

Hyphenation only works where the language is declared — this page and the site are both <html lang="nl">, so the measurement is live rather than theoretical. Safari also needs -webkit-hyphens, which this file now sets; adding it changed no result.

Round 6 — does 3/2 fit every card?

★ Locked — 2026-08-12 — the type size picks the pair

Normal type takes headline 3 / lead 2 / meta 1. Small type (≤12px) takes 2 / 1 / 1. It keys on the same idea round 2 locked — there the register named the bucket, here the size names the pair — so it is one idea applied twice rather than two unrelated rules, and it needs no maintained list of "compact" components. It ratifies all six small-type slots exactly as they ship today, so the change lands only on the full cards, which is where the contradiction actually was. The meta line gets the value it already has everywhere: 1.
