Decks and agate, built only from what the contract returns

Every row below traces to a field in packages/api-contract/src/schemas/match.ts. Nothing is authored in Sanity, nothing is inferred, and the two rows I invented on the last page — referee and attendance — are gone, because MatchDetail has no such fields.

What MatchDetail actually carries

Green rows are guaranteed by the schema. Red rows are what the previous mockup invented. Everything else is S.optional, which means it is a dash, not a hole.

Rendered as Contract field Required Note
Head — team names home_team.name · away_team.name yes MatchTeam.name is S.String, not optional.
Deck 1 — date date yes DateFromStringOrDate, required. Belgian wall-clock — read the weekday off UTC, never setZone.
Deck 2 — status status yes Six values. Wording comes from matchStatusWording() so the hero and an agenda row cannot spell "Forfait" differently (#2423).
Deck 1 — kickoff time optional Appended to the date deck when present; the deck stands without it.
Agate — Reeks competition optional A division name ("3de Nationale"), never "Competitie". Frequently absent on match detail — reliable only on the season-games list. This is the dash you will actually see.
Agate — Type competitionType optional league · cup · friendly · other. Gate on this, never on the label string.
Agate — Terrein venue optional PRODUCT.md names venue explicitly as a field "the upstream does not reliably provide … must never be designed into a layout as guaranteed".
Agate — Ploeg kcvv_team_label optional "A-Ploeg", "U21". Computed by the BFF.
Agate — Thuis / Uit is_home optional Absent on match detail in practice — derive from the club id rather than letting undefined take the falsy branch.
Agate — Stand home_team.score · away_team.score optional undefined ≠ 0. "Played but unreported" is a real state and gets a dash, not "0–0".
Agate — Doelpunten events[] type="goal" optional Carries minute, player?, isPenalty?, isOwnGoal?. The player name itself is optional.
Agate — Kaarten events[] yellow/second_yellow/red optional second_yellow is distinct from red_card by design.
Agate — Verslag hasReport yes A required boolean — the one always-answerable yes/no besides status.
Scheidsrechter — no such field — invented Not in MatchDetail, not in BaseMatchFields. Removed.
Toeschouwers — no such field — invented Not in the contract, and PRODUCT.md forbids fabricating attendance figures outright. Removed.

The rule this produces

Only three things can go in a deck: the team names, the date, and the status. Those are the entire required set. Everything else is optional, so it belongs in the table, where an absent value is an honest dash instead of a gap in a headline.

That is not a compromise — it is the same split a 1912 sports page made for a different reason. Identity in the decks, statistics in the agate.

The block, in the two states that actually occur

Same component. A fixture has no events and no score; a played match has both. The dashes are real — competition is usually missing on match detail.

What this costs and what it removes. The decks are three guaranteed fields, so they never render empty and never need a fallback. The agate table is built by filtering present fields, not by templating a fixed row list — so it shrinks rather than gaps. And because it sits below the head rather than beside it, none of this touches the horizontal band that #2598 is about: the right-hung version was the only one with that exposure, and it is gone.
